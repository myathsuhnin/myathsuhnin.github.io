Identity Threat Detection: Defending the Keys to the Kingdom

Threat Detection Engineering • SIEM Analytics • Identity & Access Management (IAM)

MITRE ATT&CK Matrix: T1078 (Valid Accounts), T1558 (Steal or Modify Authentication Material)

Scenario Objective

An external threat actor successfully establishes an initial foothold on an internal corporate workstation. Rather than launching disruptive malware, the attacker attempts a stealthy Lateral Movement strategy, actively hunting for unmanaged administrative credentials and trying to compromise or bypass the centralized CyberArk Privileged Access Management (PAM) architecture to gain Domain Admin privileges.

This playbook establishes the exact SIEM logic (KQL / SPL) and log correlation strategies a Security Operations Center (SOC) must deploy to detect and contain this identity-based attack pattern before a total domain compromise occurs.

SIEM Correlation & Detection Engineering

As a Blue Team Analyst, networks cannot be monitored in isolation. Defensive pipelines require correlating perimeter boundary events (Firewall) with host authentication engines (Windows Active Directory) and centralized vault audit trails (CyberArk PAM).

Phase 1: Detecting Boundary Reconnaissance (Perimeter Logs)

Platform: Splunk Search (SPL)

index=firewall action=deny src_zone=outside
| stats count by src_ip, dest_ip, dest_port
| where count > 100
| rename src_ip as Attacker_IP, dest_ip as Targeted_Server

Operational Rationale: Isolates external public IPs executing high-volume port scanning or rapid service probing against restricted internal network segments within a compressed temporal window.

Phase 2: Detecting Privilege Escalation via Windows Event IDs

Platform: Microsoft Sentinel (KQL)

SecurityEvent
| where EventID in (4625, 4728, 4732)
| summarize FailedLogins = countif(EventID == 4625), AccountElevations = countif(EventID in (4728, 4732)) by Account, SourceComputer, IpAddress
| where FailedLogins > 20 or AccountElevations > 0

Operational Rationale: Tracks anomalous, high-frequency authentication failures (EventID 4625) or unauthorized modifications to sensitive domain security configurations (EventID 4728 / 4732) indicative of account hijacking.

Phase 3: Catching the PAM Vault Bypass (CyberArk Audit Logs)

Platform: Cross-Platform Correlation Logic (KQL)

CyberArkAuditLogs
| where Action == "Retrieve Password" or Action == "Logon Failed"

| extend IsAdministrativeSafe = TargetSafe matches regex @"(?i)(Domain_Admin|Vault_Admin|Root_Keys)"
| project TimeGenerated, User, Action, TargetSafe, SourceAddress, IsAdministrativeSafe
| order by TimeGenerated desc

Operational Rationale: Instantly isolates credential retrieval queries executed against highly critical root directories (IsAdministrativeSafe) outside regular operating baselines, bridging infrastructure operations directly into alerting logic.

Executive Containment & Response Playbook

1. Triage & Verification Cross-check the triggering source IP metrics against change-management database layers to isolate scheduled asset onboarding actions. If unverified, declare a True Positive event.
2. Host Isolation Issue a centralized EDR instruction to network-isolate the compromised host node immediately, severing the attacker's interactive command-and-control connection lines.
3. Boundary Lockdown Force an immediate session termination and credential rotation sequence across identified accounts, deploying emergency host blocks across adjacent network nodes.
