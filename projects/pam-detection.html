Identity Threat Detection: Defending the Keys to the Kingdom

Focus Area: Threat Detection Engineering, SIEM Analytics, Identity & Access Management (IAM)

🎯 MITRE ATT&CK Matrix: T1078 (Valid Accounts), T1558 (Steal or Modify Authentication Material)

🚨 Scenario Objective

An external threat actor successfully establishes an initial foothold on an internal corporate workstation. Rather than launching loud malware, the attacker attempts a stealthy Lateral Movement strategy, actively hunting for unmanaged administrative credentials and trying to compromise or bypass the centralized CyberArk Privileged Access Management (PAM) architecture to gain Domain Admin rights.

This playbook establishes the exact SIEM logic (KQL / SPL) and log correlation strategies a Security Operations Center (SOC) must deploy to detect and contain this identity-based attack pattern before a total domain compromise occurs.

🔬 SIEM Correlation & Detection Engineering

As a Blue Team Analyst, we do not monitor systems in isolation. We correlate boundary logs (Firewall) with host authentication logs (Windows Active Directory) and platform audit logs (CyberArk PAM).

Phase 1: Detecting Boundary Reconnaissance (Perimeter Logs)

Platform: Splunk Search (SPL)

index=firewall action=deny src_zone=outside
| stats count by src_ip, dest_ip, dest_port
| where count > 100
| rename src_ip as Attacker_IP, dest_ip as Targeted_Server

Operational Rationale: Isolates external public IPs performing heavy port-scanning or service probing against critical internal network segments within a compressed time window.

Phase 2: Detecting Privilege Escalation via Windows Event IDs

Platform: Microsoft Sentinel (KQL)

SecurityEvent
| where EventID in (4625, 4728, 4732)
| summarize FailedLogins = countif(EventID == 4625), AccountElevations = countif(EventID in (4728, 4732)) by Account, SourceComputer, IpAddress
| where FailedLogins > 20 or AccountElevations > 0

Operational Rationale: Tracks sudden, high-volume brute-force attempts (EventID 4625) or anomalous additions of standard domain accounts into highly privileged security groups (EventID 4728 / 4732) like Domain Admins.

Phase 3: Catching the PAM Vault Bypass (CyberArk Audit Logs)

Platform: Cross-Platform Correlation Logic (KQL)

CyberArkAuditLogs
| where Action == "Retrieve Password" or Action == "Logon Failed"

| extend IsAdministrativeSafe = TargetSafe matches regex @"(?i)(Domain_Admin|Vault_Admin|Root_Keys)"
| project TimeGenerated, User, Action, TargetSafe, SourceAddress, IsAdministrativeSafe
| order by TimeGenerated desc

Operational Rationale: Instantly triggers a high-severity SOC alert if a password retrieval action occurs on a highly restricted administrative safe (IsAdministrativeSafe) outside of standard business hours, leveraging real-world environment knowledge to mitigate exposure.

📋 Executive Containment & Response Playbook

1. Triage & Verification: Cross-check the source IP address against internal enterprise change-management records to verify if an infrastructure team member is performing scheduled operational account onboarding. If unverified, classify immediately as a True Positive event.

2. Host Isolation: Trigger an immediate endpoint threat response payload to network-isolate the compromised host asset, cutting off active command-and-control connection streams.

3. Credential Revocation & Boundary Lock: Enforce session termination and password rotations across administrative directory structures, temporarily executing firewall port blocks to isolate administrative cluster nodes.
